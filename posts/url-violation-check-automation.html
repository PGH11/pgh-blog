    Python + Playwright：多语言 URL 违规内容自动检测实战

    自动化测试2026年1月25日

    对于多语言站点来说，内容合规性是一个非常重要但也极其繁琐的测试点。手动检查 10 种语言 × 1000 个页面的违规内容？根本不可能。本文分享我基于 Playwright 开发的多线程 URL 内容扫描脚本，让违规内容检测完全自动化。

    一、需求背景

    在做国际站项目时，我们经常遇到以下合规性检查需求：

    • 检查页面是否包含违禁词、敏感词
    • 验证特定区域的法规合规性（GDPR、CCPA 等）
    • 检查不同语言下的免责声明是否存在
    • 验证价格、版权等信息是否完整
    • 确保上线内容不包含测试数据或占位符

    当站点支持 10 种以上语言、有数千个页面时，人工检查是不现实的。我们需要一个自动化方案。

    二、技术选型

    经过多次实践，我最终选择了以下技术栈：

    核心技术：
    • Playwright - 浏览器自动化，支持多语言渲染
    • concurrent.futures - Python 原生多线程
    • BeautifulSoup - HTML 内容解析

    为什么选 Playwright？
    • 支持多种语言的正确渲染
    • 能执行 JS，获取完整渲染后的页面内容
    • 自动等待页面加载，稳定性高
    • 多线程环境下表现良好

    三、核心实现思路

    3.1 从 Sitemap 提取 URL

    首先需要获取站点的所有页面 URL。使用 sitemap.xml 是最标准的方式：

    import requests
from xml.etree import ElementTree

def extract_urls_from_sitemap(sitemap_url):
    """从 sitemap.xml 提取所有 URL"""
    response = requests.get(sitemap_url)
    root = ElementTree.fromstring(response.content)
    
    # 处理 sitemap 嵌套的情况
    namespaces = {'sm': 'http://www.sitemaps.org/schemas/sitemap/0.9'}
    urls = []
    
    # 检查是否是 sitemap index
    sitemap_tags = root.findall('sm:sitemap', namespaces)
    if sitemap_tags:
        # 递归提取子 sitemap
        for sitemap in sitemap_tags:
            loc = sitemap.find('sm:loc', namespaces).text
            urls.extend(extract_urls_from_sitemap(loc))
    else:
        # 提取 URL
        for url_tag in root.findall('sm:url', namespaces):
            loc = url_tag.find('sm:loc', namespaces).text
            urls.append(loc)
    
    return urls

    这个函数支持 sitemap 嵌套，对于大型站点特别有用。提取完成后可以导出为 JSON 文件。

    3.2 违规词检测核心逻辑

    class ViolationChecker:
    def __init__(self, violation_keywords):
        self.keywords = violation_keywords
        
    def check_page(self, page_content):
        """检查页面是否包含违规内容"""
        violations = []
        
        for keyword in self.keywords:
            if keyword.lower() in page_content.lower():
                violations.append(keyword)
        
        return violations
    
    def check_xpath_element(self, page, xpath, expected_texts):
        """检查特定 XPath 元素是否包含预期文本"""
        try:
            element = page.locator(xpath)
            if element.count() == 0:
                return ["元素不存在"]
            
            text = element.inner_text()
            violations = []
            for expected in expected_texts:
                if expected not in text:
                    violations.append(f"缺少预期文本: {expected}")
            
            return violations
        except Exception as e:
            return [f"检查失败: {str(e)}"]

    3.3 多线程并发扫描

    单线程扫描太慢了，1000 个页面可能要跑半小时。使用多线程可以大幅提升速度：

    from concurrent.futures import ThreadPoolExecutor, as_completed
from playwright.sync_api import sync_playwright

def scan_single_url(url, checker):
    """扫描单个 URL"""
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        page = browser.new_page()
        
        try:
            page.goto(url, timeout=30000)
            page.wait_for_load_state('networkidle')
            
            # 获取页面完整内容
            content = page.content()
            
            # 检查违规内容
            violations = checker.check_page(content)
            
            return {
                'url': url,
                'status': 'success',
                'violations': violations,
                'violation_count': len(violations)
            }
            
        except Exception as e:
            return {
                'url': url,
                'status': 'error',
                'error': str(e),
                'violations': []
            }
        finally:
            browser.close()

def batch_scan(urls, max_workers=5):
    """批量扫描"""
    checker = ViolationChecker(get_violation_keywords())
    results = []
    
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        future_to_url = {
            executor.submit(scan_single_url, url, checker): url 
            for url in urls
        }
        
        for future in as_completed(future_to_url):
            url = future_to_url[future]
            try:
                result = future.result()
                results.append(result)
                print(f"✅ {url} - 发现 {result['violation_count']} 个违规")
            except Exception as e:
                print(f"❌ {url} - 扫描失败: {e}")
                results.append({
                    'url': url, 
                    'status': 'exception', 
                    'error': str(e)
                })
    
    return results

    3.4 报告生成

    扫描完成后，生成清晰的检测报告：

    def generate_report(results, output_file):
    """生成 HTML 检测报告"""
    
    # 统计数据
    total = len(results)
    success = len([r for r in results if r['status'] == 'success'])
    has_violation = len([r for r in results if r.get('violation_count', 0) > 0])
    
    html = f"""
    
    
        
        违规内容检测报告
        
    
    
        
    违规内容检测报告
    
        
    
            
    总 URL 数: {total}
    
            
    扫描成功: {success}
    
            
    发现违规: {has_violation}
    
        
    
        ...
    
    </body>
    </html>
    """
    
    with open(output_file, 'w', encoding='utf-8') as f:
        f.write(html)

    四、多语言适配

    对于多语言站点，需要额外处理：

    1. 按语言分组扫描，不同语言使用不同的违规词表
    2. 检测语言切换功能是否正常工作
    3. 验证特定语言下必须存在的合规文案（如免责声明）
    def scan_multilingual(base_url, languages, checker):
    """多语言站点扫描"""
    results = {}
    
    for lang in languages:
        lang_url = f"{base_url}/{lang}/"
        print(f"开始扫描 {lang} 语言版本...")
        
        # 提取该语言的 sitemap URL
        sitemap_url = f"{base_url}/{lang}/sitemap.xml"
        urls = extract_urls_from_sitemap(sitemap_url)
        
        # 批量扫描
        lang_results = batch_scan(urls, max_workers=3)
        results[lang] = lang_results
        
        # 输出该语言统计
        violations = sum(r.get('violation_count', 0) for r in lang_results)
        print(f"{lang} 完成: 发现 {violations} 个违规")
    
    return results

    五、最佳实践

    5.1 并发控制

    线程数不是越大越好！建议：

    • 生产环境：3~5 个线程
    • 测试环境：5~8 个线程
    • 避免给服务器造成过大压力

    5.2 错误重试

    网络波动是正常的，给每个 URL 增加重试机制：

    def scan_with_retry(url, checker, max_retries=3):
    for attempt in range(max_retries):
        try:
            return scan_single_url(url, checker)
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            print(f"重试 {attempt + 1}/{max_retries}: {url}")
            time.sleep(2 ** attempt)  # 指数退避

    5.3 增量扫描

    不要每次都全量扫描！记录上次扫描时间，只扫描新增或变更的页面：

    def get_urls_to_scan(all_urls, last_scan_time):

    # 这里可以对接 CMS API，获取页面最后更新时间

    import random
    sample_size = min(100, len(all_urls))
    return random.sample(all_urls, sample_size)

    六、与 CI/CD 集成

    将违规内容检查集成到发布流水线中：

    # .github/workflows/violation-check.yml
name: 违规内容检查

on:
  schedule:
    - cron: '0 2 * * *'  # 每天凌晨 2 点执行
  workflow_dispatch:      # 支持手动触发

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: 设置 Python
        uses: actions/setup-python@v4
        with: { python-version: '3.11' }
      
      - name: 安装依赖
        run: |
          pip install -r requirements.txt
          playwright install chromium
      
      - name: 执行扫描
        run: python scripts/check_urls_violations.py
      
      - name: 上传报告
        uses: actions/upload-artifact@v3
        with:
          name: violation-report
          path: reports/violation-report.html
      
      - name: 发现违规时告警
        if: failure()
        run: |
          # 发送 Slack/邮件通知
          echo "发现违规内容，请查看报告！"

    七、实际效果

    使用这套方案后，我们的测试效率有了质的飞跃：

    • 覆盖范围：从只能抽检 10 个页面 → 全量扫描 1000+ 页面
    • 执行时间：从 2 人天 → 30 分钟自动完成
    • 发现问题：上线后累计发现 50+ 人工漏测的合规性问题
    • 回归成本：每次发布回归时间从 4 小时 → 0

    八、进阶优化方向

    • AI 语义检测：接入 OpenAI API，不仅仅是关键词匹配，而是语义层面的合规检查
    • 图片 OCR：对页面中的图片也进行违规内容检测
    • 历史对比：对比两次扫描结果，只报告新增的违规项
    • 自定义规则引擎：支持更复杂的合规规则配置

    总结

    内容合规性检测是一个容易被忽略但风险很高的测试领域。通过 Playwright + Python 多线程的方案，我们可以将繁琐的人工检查转变为高效、可靠的自动化流程。
