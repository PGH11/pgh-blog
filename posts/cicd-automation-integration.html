CI/CD 流水线中的自动化测试集成策略

最佳实践2023年12月10日

将自动化测试集成到 CI/CD 流水线中是实现持续交付的关键一环。本文将分享如何在 GitHub Actions、GitLab CI 等平台中高效集成自动化测试，以及如何处理测试分层、并行执行等优化技巧。

一、测试分层策略

并非所有测试都需要在每次提交时执行。合理的测试分层策略是提高流水线效率的关键：

  • 单元测试（Unit Tests）：每次提交必跑，快速反馈
  • 接口测试（API Tests）：每次 PR 执行，验证业务逻辑
  • 集成测试（Integration Tests）：每日定时或合并前执行
  • E2E 测试（End-to-End）：每日定时或发布前执行，耗时较长
  • 性能测试（Performance Tests）：每周或版本发布前执行

二、GitHub Actions 集成示例

name: CI Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  unit-tests:
    name: 单元测试
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
        with: { python-version: '3.11' }
      - run: pip install -r requirements.txt
      - run: pytest tests/unit/ -v --cov=src

  api-tests:
    name: 接口测试
    needs: unit-tests
    runs-on: ubuntu-latest
    services:
      api:
        image: myapp/api:latest
        ports: ['8000:8000']
        env: { ENV: test }
    steps:
      - uses: actions/checkout@v3
      - run: pip install -r requirements.txt
      - run: pytest tests/api/ -v

  e2e-tests:
    name: E2E 测试
    needs: api-tests
    runs-on: ubuntu-latest
    if: github.event_name == 'schedule' || contains(github.event.pull_request.labels.*.name, 'run-e2e')
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
      - run: pip install -r requirements.txt
      - run: playwright install chromium
      - run: pytest tests/e2e/ -v
      - uses: actions/upload-artifact@v3
        if: failure()
        with: { name: e2e-screenshots, path: outputs/screenshots/ }

三、测试执行优化

1. 并行执行

使用 pytest-xdist 实现测试用例并行执行，大幅缩短执行时间：

pytest tests/ -n auto  # 自动使用 CPU 核心数

2. 失败重试

对于不稳定的 E2E 测试，配置自动重试：

pytest tests/e2e/ --reruns 2 --reruns-delay 5

3. 测试分片

在多机环境中按文件分片执行：

# Worker 1
pytest tests/ --shard-id=1 --num-shards=4

# Worker 2  
pytest tests/ --shard-id=2 --num-shards=4

四、测试报告与反馈

  • 测试结果自动评论到 PR 中
  • 失败时自动上传截图和日志作为 Artifact
  • 将测试覆盖率报告推送到 Codecov 等平台
  • 测试失败时通知相关开发人员

五、常见问题处理

  • 测试环境准备：使用 Docker Compose 一键启动依赖服务
  • Flaky Tests：记录失败历史，识别不稳定测试
  • 测试数据：使用独立的测试数据库，每次测试前重置
  • 执行时间：设置合理的超时，避免流水线卡死

CI/CD 中的自动化测试不是为了 100% 覆盖率，而是为了给团队提供快速、可靠的质量反馈，让发布变得更有信心。
