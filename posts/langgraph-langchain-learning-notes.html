    LangGraph 与 LangChain 学习笔记

    AI 开发2026年5月11日

    这份文档结合当前目录里的 image_agent.py，解释脚本里 LangChain 和 LangGraph 分别做什么，以及一次用户对话是怎么被送进 AI、怎么更新状态、怎么最终调用接口的。

    一句话理解

    在这个脚本里：

    • LangChain 负责和大模型交互：创建模型客户端、组织消息、调用 AI、拿结构化输出。
    • LangGraph 负责流程编排：定义状态、节点、分支，让一轮对话按固定流程运行。
    • Pydantic 负责数据结构：约束 AI 必须返回什么字段，避免只返回一段不可控文本。
    • 普通 Python 负责业务逻辑：合并参数、生成签名、调用 LitMedia 接口。

    可以理解成：

    LangChain = 模型调用层 LangGraph = 状态机编排层 Pydantic = 数据协议层 Python = 业务执行层

    当前脚本的整体流程

    用户每输入一句话，脚本会跑一次 LangGraph：

    User 输入 ↓ intent_router ↓ 根据 route 分支 ├─ chat_responder └─ creative_worker ↓ END

    如果用户是在闲聊，比如：

    你能帮我干嘛？

    会走：

    intent_router -> chat_responder -> END

    如果用户是在创作视频，比如：

    我想生成一个关于小狗的视频

    会走：

    intent_router -> creative_worker -> END

    当用户最终确认后，CLI 会在 LangGraph 之外调用：

    call_litmedia_text_video()

    1. LangChain 在脚本里的作用

    1.1 创建模型客户端

    脚本里通过 ChatOpenAI 创建模型：

    llm = ChatOpenAI(
    api_key=ark_api_key,
    base_url=os.getenv(
        "ARK_BASE_URL",
        "https://ark.cn-beijing.volces.com/api/coding/v3",
    ),
    model=os.getenv("ARK_MODEL", "ark-code-latest"),
    temperature=0,
)

    虽然类名叫 ChatOpenAI，但这里配置了 Ark 的 base_url，所以实际是通过 OpenAI 兼容协议调用 Ark 模型。

    这里的关键参数：

    • api_key：模型调用密钥。
    • base_url：模型接口地址。
    • model：模型名称。
    • temperature=0：降低随机性，让结构化任务更稳定。

    1.2 组织消息上下文

    LangChain 使用消息对象和模型对话：

    from langchain_core.messages import (
    AIMessage,
    HumanMessage,
    SystemMessage,
)

# 系统提示词
system_prompt = SystemMessage(content="...")

# 用户消息
user_msg = HumanMessage(content="生成一个小狗视频")

# 组装
messages = [system_prompt, user_msg]

# 调用
ai_resp = llm.invoke(messages)
print(ai_resp.content)

    脚本里每个节点都会做一次组装 → 调用 → 解析的流程。

    1.3 结构化输出

    如果直接让 AI 回答问题，它返回的是一串文本，后续代码很难稳定地、自动化地去使用。

    LangChain 可以把 Pydantic 模型绑定到调用链上，强制 AI 返回符合 JSON Schema 的内容，这样后续代码就可以像操作普通对象一样使用 AI 的输出。

    在脚本里：

    # Pydantic 模型定义
class IntentRouterOutput(BaseModel):
    route: Literal["chat", "creative"] = Field(
        ..., description="用户输入分类：chat 或 creative"
    )

# 让 LLM 绑定这个输出结构
router_chain = llm.with_structured_output(IntentRouterOutput)

# 调用后直接得到对象
output = router_chain.invoke(messages)

print(output.route)  # "chat" 或 "creative"

    有了这个机制，后续节点才可以稳定地做分支判断。

    2. LangGraph 在脚本里的作用

    2.1 定义状态

    LangGraph 的核心是 State。整个图运行过程中，所有节点都读取或修改同一个状态对象。

    在脚本里：

    class AgentState(TypedDict):
    messages: list[AIMessage | HumanMessage | SystemMessage]
    creative_params: CreativeParams | None
    user_input: str
    • messages：对话历史，每个节点都会往里面追加新消息。
    • creative_params：当前已经确定的内容参数。
    • user_input：用户最新输入的一句话。

    所有节点看到的是同一份状态，节点执行完返回的值会合并（更新）到状态里。

    2.2 创建节点

    节点就是 LangGraph 里的一个可执行步骤，通常会做三件事：

    1. 从 state 里读取当前需要的数据。
    2. 调用 LangChain 向模型提问，拿到结构化输出。
    3. 把结果更新回 state，交给下一个节点。

    以 intent_router 为例：

    def intent_router(state: AgentState) -> dict:
    messages = state["messages"]

    # 调用 LangChain，拿到结构化输出
    output = router_chain.invoke(messages)

    # 把 AI 回答追加到消息历史
    ai_message = AIMessage(
        content=json.dumps(output.model_dump(), ensure_ascii=False),
    )
    messages.append(ai_message)

    # 返回新状态，LangGraph 会自动合并
    return {
        "messages": messages,
        "route": output.route,
    }

    2.3 条件边：分支

    如果流程需要根据前一个节点的结果选择下一个节点，可以用条件边：

    def route_decision(state: AgentState) -> str:
    # 这里 state 已经包含了 intent_router 写入的 route
    return state["route"]

# 把条件边注册到图里
builder.add_conditional_edges(
    "intent_router",
    route_decision,
    {
        "chat": "chat_responder",
        "creative": "creative_worker",
    },
)

    这样当用户输入不同内容时，图会自动走到不同分支。

    2.4 编译和调用

    定义好节点和边之后，编译成可执行图：

    graph = builder.compile()

# 调用
initial_state = {
    "messages": [user_input],
    "creative_params": None,
    "user_input": user_input,
}

result = graph.invoke(initial_state)

    result 就是最终的状态快照，包含所有节点留下的结果。

    3. 一次完整的调用过程

    以用户说「我想生成一个小狗视频」为例：

    步骤 1：初始化状态

    state = { "messages": [HumanMessage("我想生成一个小狗视频")], "creative_params": None, "user_input": "我想生成一个小狗视频", }

    步骤 2：进入 intent_router
