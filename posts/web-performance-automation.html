Web 页面冷启动性能自动化测试实践

性能测试2026年1月20日

页面加载速度直接影响用户体验和 SEO 排名。但性能测试往往需要专业工具和复杂配置，难以集成到日常开发流程中。本文分享我基于 Performance API 开发的轻量级页面冷启动性能测试方案，让每个开发都能轻松做性能测试。

一、为什么要做自动化性能测试？

性能问题往往是"温水煮青蛙"，在开发过程中不知不觉就变慢了：

  • 引入一个新组件，页面加载时间增加了 200ms
  • 新增第三方 SDK，阻塞了主线程
  • 图片忘记压缩，首屏加载变慢
  • Webpack 配置变更，打包体积突然变大

等到上线后再发现性能退化，回滚成本很高。我们需要在每次提交时就能自动检测这些问题。

二、核心性能指标

基于浏览器 Performance API，我们重点关注这些指标：

📊 关键性能指标

  • DOMContentLoaded - DOM 解析完成时间
  • Load - 页面所有资源加载完成时间
  • First Paint (FP) - 首次绘制时间
  • First Contentful Paint (FCP) - 首次内容绘制时间
  • Largest Contentful Paint (LCP) - 最大内容绘制时间
  • 资源加载统计 - JS/CSS/图片的数量和大小

三、Performance API 使用方法

// 在浏览器中执行获取性能数据
function getPerformanceMetrics() {
    const timing = performance.timing;
    const navigation = performance.getEntriesByType('navigation')[0];
    const paint = performance.getEntriesByType('paint');
    const resources = performance.getEntriesByType('resource');
    
    return {
        // 页面加载指标
        domContentLoaded: timing.domContentLoadedEventEnd - timing.navigationStart,
        loadComplete: timing.loadEventEnd - timing.navigationStart,
        domReady: timing.domComplete - timing.navigationStart,
        
        // 绘制指标
        firstPaint: paint.find(p => p.name === 'first-paint')?.startTime,
        firstContentfulPaint: paint.find(p => p.name === 'first-contentful-paint')?.startTime,
        
        // 资源统计
        resourceCount: resources.length,
        totalTransferSize: resources.reduce((sum, r) => sum + (r.transferSize || 0), 0),
        jsResources: resources.filter(r => r.initiatorType === 'script').length,
        cssResources: resources.filter(r => r.initiatorType === 'css').length,
        imageResources: resources.filter(r => r.initiatorType === 'img').length,
        
        // 慢资源列表（超过 1s）
        slowResources: resources
            .filter(r => r.duration > 1000)
            .map(r => ({ name: r.name, duration: r.duration }))
    };
}

四、Python 自动化测试实现

使用 Playwright 控制浏览器，自动采集性能数据：

from playwright.sync_api import sync_playwright
import json
import statistics

class PerformanceTester:
    def __init__(self, base_url):
        self.base_url = base_url
        self.results = []
    
    def test_single_page(self, path, runs=3):
        """测试单个页面，多次运行取中位数"""
        url = f"{self.base_url}{path}"
        print(f"测试页面: {url} (运行 {runs} 次)")
        
        metrics_list = []
        
        with sync_playwright() as p:
            browser = p.chromium.launch(
                headless=True,
                args=['--disable-cache', '--disable-extensions']  # 冷启动模式
            )
            
            for i in range(runs):
                # 每次都新建上下文，确保冷启动
                context = browser.new_context()
                page = context.new_page()
                
                # 禁用缓存
                page.set_extra_http_headers({'Cache-Control': 'no-cache'})
                
                # 访问页面
                page.goto(url, wait_until='load')
                
                # 等待 LCP 稳定
                page.wait_for_timeout(2000)
                
                # 采集性能数据
                metrics = page.evaluate("""() => {
                    const timing = performance.timing;
                    const paint = performance.getEntriesByType('paint');
                    const resources = performance.getEntriesByType('resource');
                    
                    return {
                        domContentLoaded: timing.domContentLoadedEventEnd - timing.navigationStart,
                        loadComplete: timing.loadEventEnd - timing.navigationStart,
                        firstPaint: paint.find(p => p.name === 'first-paint')?.startTime || 0,
                        firstContentfulPaint: paint.find(p => p.name === 'first-contentful-paint')?.startTime || 0,
                        resourceCount: resources.length,
                        totalSize: resources.reduce((sum, r) => sum + (r.transferSize || 0), 0)
                    };
                }""")
                
                metrics_list.append(metrics)
                print(f"  运行 {i+1}: FCP = {metrics['firstContentfulPaint']:.0f}ms")
                
                context.close()
            
            browser.close()
        
        # 计算中位数结果，消除抖动
        result = {
            'url': url,
            'path': path,
            'runs': runs,
            'domContentLoaded': self._median([m['domContentLoaded'] for m in metrics_list]),
            'loadComplete': self._median([m['loadComplete'] for m in metrics_list]),
            'firstPaint': self._median([m['firstPaint'] for m in metrics_list]),
            'firstContentfulPaint': self._median([m['firstContentfulPaint'] for m in metrics_list]),
            'resourceCount': self._median([m['resourceCount'] for m in metrics_list]),
        }
        
        self.results.append(result)
        return result
    
    def _median(self, values):
        """计算中位数"""
        return statistics.median(sorted(values))
    
    def generate_report(self, output_file):
        """生成性能报告"""
        # 计算整体统计
        all_fcp = [r['firstContentfulPaint'] for r in self.results]
        
        report = {
            'summary': {
                'total_pages': len(self.results),
                'avg_fcp': sum(all_fcp) / len(all_fcp),
                'max_fcp': max(all_fcp),
                'min_fcp': min(all_fcp),
            },
            'pages': self.results,
            'warnings': self._generate_warnings(),
        }
        
        # 保存 JSON
        with open(output_file, 'w', encoding='utf-8') as f:
            json.dump(report, f, indent=2, ensure_ascii=False)
        
        # 生成 HTML 报告
        self._generate_html_report(report, output_file.replace('.json', '.html'))
        
        return report
    
    def _generate_warnings(self):
        """生成性能告警"""
        warnings = []
        
        for result in self.results:
            if result['firstContentfulPaint'] > 2000:
                warnings.append({
                    'level': 'warning',
                    'page': result['path'],
                    'message': f"FCP 超过 2s: {result['firstContentfulPaint']:.0f}ms"
                })
            
            if result['loadComplete'] > 5000:
                warnings.append({
                    'level': 'danger',
                    'page': result['path'],
                    'message': f"页面加载超过 5s: {result['loadComplete']:.0f}ms"
                })
        
        return warnings

五、批量测试与基线对比

测试核心页面并与历史基线对比：

def run_performance_test():
    """运行完整性能测试"""
    tester = PerformanceTester("https://example.com")
    
    # 核心页面列表
    pages_to_test = [
        '/',
        '/products',
        '/about',
        '/contact',
        '/blog',
    ]
    
    print("开始性能测试...")
    for path in pages_to_test:
        tester.test_single_page(path, runs=3)
    
    # 生成报告
    report = tester.generate_report('reports/performance.json')
    
    # 与基线对比
    baseline = load_baseline()
    if baseline:
        compare_with_baseline(report, baseline)
    
    # 输出告警
    if report['warnings']:
        print("\n⚠️  发现性能问题:")
        for w in report['warnings']:
            print(f"  [{w['level']}] {w['page']}: {w['message']}")
    else:
        print("\n✅ 所有页面性能正常")
    
    # 如果有严重告警，返回非 0 退出码
    has_danger = any(w['level'] == 'danger' for w in report['warnings'])
    exit(1 if has_danger else 0)

六、CI 流水线集成

将性能测试集成到每次 PR 中：

# .github/workflows/performance.yml
name: 性能测试

on:
  pull_request:
    branches: [main]

jobs:
  performance-test:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: 安装依赖
        run: |
          pip install -r requirements.txt
          playwright install chromium
      
      - name: 启动本地服务
        run: |
          npm run build
          npm run preview -- --port 3000 &
      
      - name: 等待服务启动
        run: npx wait-on http://localhost:3000
      
      - name: 运行性能测试
        run: python scripts/performance_test.py
      
      - name: 上传性能报告
        uses: actions/upload-artifact@v3
        with:
          name: performance-report
          path: reports/

八、常见问题与解决方案

8.1 测试结果不稳定？

性能测试结果有波动是正常的，建议：

  • 多次运行取中位数（3~5 次）
  • 在 CI 中使用同一规格的机器执行
  • 关闭浏览器缓存，模拟冷启动
  • 排除第三方广告/统计脚本的干扰

8.2 如何定位性能瓶颈？

  • 用 Performance API 的 resource 数据，找出加载最慢的资源
  • 用 Playwright 的 trace 功能录制完整的加载过程
  • 集成 Lighthouse CI 获得更详细的优化建议

九、总结

这套自动化性能测试方案的优势：

  • 轻量级：无需复杂的性能测试平台，纯 Python 脚本即可实现
  • 标准化：基于浏览器标准 API，数据准确可靠
  • 易集成：轻松接入 CI 流水线，每次 PR 自动检测
  • 可扩展：可以轻松添加更多指标和检测规则

性能优化不是一次性的工作，而是需要持续关注。通过自动化性能测试，我们可以在开发阶段就发现性能退化问题，避免上线后再花几倍的时间去修复。
