企业级 Pytest 自动化测试框架设计指南

框架设计 2024年1月8日

Pytest 是 Python 生态中最流行的测试框架之一，其简洁的语法、强大的插件系统 和灵活的 Fixture 机制使其成为构建企业级自动化测试框架的首选。本文将分享 如何从零开始设计一个可扩展、易维护的 Pytest 自动化测试框架。

一、框架设计原则

好的测试框架应该让编写测试变得简单，让维护测试变得轻松， 让测试结果值得信赖。

核心设计原则

  • 可扩展性：支持新功能模块快速接入，无需修改核心代码
  • 可维护性：代码结构清晰，命名规范，文档完善
  • 可读性：测试用例表达业务意图，而非技术细节
  • 稳定性：减少非预期失败，提供可靠的测试结果
  • 可观测性：完善的日志和报告，便于定位问题

三、核心模块实现

1. 配置管理

使用 PyYAML 加载配置，支持多环境切换：

# core/config.py
import yaml
import os
from typing import Dict

class Config:
    _instance = None
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance._load_config()
        return cls._instance
    
    def _load_config(self):
        env = os.getenv('TEST_ENV', 'test')
        config_path = f'config/{env}.yaml'
        
        with open(config_path, 'r', encoding='utf-8') as f:
            self._config = yaml.safe_load(f)
        
        # 加载基础配置
        with open('config/config.yaml', 'r', encoding='utf-8') as f:
            base_config = yaml.safe_load(f)
            self._config = {**base_config, **self._config}
    
    def get(self, key: str, default=None):
        keys = key.split('.')
        value = self._config
        for k in keys:
            if isinstance(value, dict):
                value = value.get(k)
            else:
                return default
        return value or default

# 使用方式
config = Config()
base_url = config.get('base_url')
timeout = config.get('timeout.default', 30)

2. Base Page 设计

封装常用操作，提供统一的元素操作接口：

# core/base_page.py
from playwright.sync_api import Page, expect
from utils.logger import logger

class BasePage:
    def __init__(self, page: Page):
        self.page = page
        self.timeout = 30000
    
    def navigate(self, url: str):
        logger.info(f"导航到: {url}")
        self.page.goto(url)
    
    def click(self, selector: str):
        logger.info(f"点击元素: {selector}")
        self.page.click(selector, timeout=self.timeout)
    
    def fill(self, selector: str, value: str):
        logger.info(f"输入文本: {selector} = {value[:20]}...")
        self.page.fill(selector, value)
    
    def get_text(self, selector: str) -> str:
        text = self.page.text_content(selector)
        logger.info(f"获取文本: {selector} = {text[:50]}...")
        return text
    
    def should_see(self, selector: str):
        expect(self.page.locator(selector)).to_be_visible()
        logger.info(f"验证元素可见: {selector}")
    
    def should_see_text(self, selector: str, text: str):
        expect(self.page.locator(selector)).to_have_text(text)
        logger.info(f"验证文本: {selector} 包含 {text}")

3. Fixture 设计

Fixtures 是 Pytest 的灵魂，合理设计 Fixture 能大幅提升效率：

# fixtures/browser_fixture.py
import pytest
from playwright.sync_api import Browser, BrowserContext, Page
from core.config import Config

@pytest.fixture(scope="session")
def browser_context(browser: Browser, request):
    """浏览器上下文 Fixture，session 级别"""
    config = Config()
    
    context = browser.new_context(
        viewport={'width': 1920, 'height': 1080},
        locale='zh-CN',
        timezone_id='Asia/Shanghai',
        record_video_dir='outputs/videos/' if config.get('record_video') else None,
        ignore_https_errors=True
    )
    
    # 设置默认超时
    context.set_default_timeout(config.get('timeout.default', 30000))
    
    yield context
    
    # 清理
    context.close()

@pytest.fixture(scope="function")
def page(browser_context: BrowserContext, request):
    """页面 Fixture，function 级别，每个测试用例独立"""
    page = browser_context.new_page()
    
    # 失败时截图
    yield page
    
    if request.node.rep_call.failed:
        screenshot_path = f"outputs/screenshots/{request.node.name}.png"
        page.screenshot(path=screenshot_path, full_page=True)
        logger.error(f"测试失败，截图已保存: {screenshot_path}")
    
    page.close()

四、测试用例编写规范

好的测试用例应该

  • 命名清晰：test_模块_场景_预期结果
  • 独立完整：不依赖其他测试用例的执行
  • 一个断言：每个测试只验证一个核心点
  • 数据隔离：使用测试数据生成器，不依赖已有数据

测试用例示例

# tests/smoke/test_login.py
import pytest
from pages.login_page import LoginPage
from pages.dashboard_page import DashboardPage
from utils.data_generator import generate_test_user

class TestLogin:
    def test_login_success_with_valid_credentials(self, page):
        """测试：使用有效凭据登录成功"""
        # 准备测试数据
        user = generate_test_user(role='admin')
        
        # 页面操作
        login_page = LoginPage(page)
        login_page.navigate()
        login_page.login(user.username, user.password)
        
        # 验证结果
        dashboard = DashboardPage(page)
        dashboard.should_see_welcome_message()
        dashboard.should_have_user_name(user.display_name)
    
    def test_login_fails_with_invalid_password(self, page):
        """测试：密码错误时登录失败"""
        login_page = LoginPage(page)
        login_page.navigate()
        login_page.login("valid_user", "wrong_password")
        
        login_page.should_see_error_message("用户名或密码错误")

五、报告集成

使用 pytest-html 或 Allure 生成精美的测试报告：

# conftest.py
import pytest
from datetime import datetime
import os

@pytest.hookimpl(tryfirst=True)
def pytest_configure(config):
    """配置 pytest，设置报告输出路径"""
    if not os.path.exists('outputs/reports'):
        os.makedirs('outputs/reports')
    
    timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
    config.option.htmlpath = f'outputs/reports/report_{timestamp}.html'
    config.option.self_contained_html = True

def pytest_html_report_title(report):
    report.title = "自动化测试报告"

def pytest_html_results_summary(prefix, summary, postfix):
    prefix.extend([
        f"
测试环境: {os.getenv('TEST_ENV', 'test')}
",
        f"
测试时间: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}
"
    ])

六、CI/CD 集成

使用 GitHub Actions 实现自动化测试执行：

# .github/workflows/automation.yml
name: Automation Tests

on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: '0 2 * * *'  # 每天凌晨 2 点执行

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
    - uses: actions/checkout@v3
    
    - name: 设置 Python
      uses: actions/setup-python@v4
      with:
        python-version: '3.11'
    
    - name: 安装依赖
      run: |
        pip install -r requirements.txt
        playwright install chromium
    
    - name: 执行测试
      env:
        TEST_ENV: test
      run: |
        pytest tests/smoke/ -v --html=outputs/reports/report.html
    
    - name: 上传测试报告
      uses: actions/upload-artifact@v3
      if: always()
      with:
        name: test-report
        path: outputs/reports/

七、最佳实践总结

1. 分层设计

将测试框架分为核心层、Page 层、测试用例层，每层只负责自己的职责。 当页面元素变化时，只需修改 Page 层，不需要改动测试用例。

2. Fixture 粒度控制

根据 Fixture 的生命周期选择合适的 scope：

  • session：浏览器实例、数据库连接池等
  • module：模块级别的测试数据
  • function：页面实例、独立测试数据等

3. 日志和截图

完善的日志是调试的关键。每个关键操作都要记录日志， 测试失败时自动截图，配合视频录制可以快速定位问题。

4. 数据驱动

使用 @pytest.mark.parametrize 实现数据驱动测试， 避免重复代码，同时覆盖更多边界场景。

八、总结

一个好的自动化测试框架不是一蹴而就的，需要在实践中持续迭代优化。 关键是建立清晰的架构规范，让团队成员能够轻松地贡献测试用例。

框架的价值不在于技术有多酷炫，而在于是否真正提高了测试效率， 是否让团队更有信心进行持续交付。
